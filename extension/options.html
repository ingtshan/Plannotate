PLANNOTATE · GITHUB ACCESS

连接 GitHub

推荐使用只覆盖需要评审仓库的 fine-grained personal access token。

尚未从 PR 获取目标仓库

1

创建正确权限的 token

在 GitHub 创建（已预填权限）
  1. Resource owner选择目标仓库的所有者
  2. Repository access选择 Only select repositories，并加入要评审的仓库
  3. Repository permissions按下表核对；不需要任何 Account 或 Organization permission
ContentsRead-only读取已提交的 plan HTML、manifest 与 anchors
Pull requestsRead and write读取、创建、回复、解决 review thread
MetadataRead-onlyGitHub 自动附加

最常见的误配：Pull requests 选成了 Read-only。这样 plan 能打开，但评论、回复和解决会报 “Resource not accessible by personal access token”。

组织仓库、外部协作者或多个 owner

组织可能要求管理员批准或 SSO 授权；pending token 只能读公共资源。一个 fine-grained token 只能绑定一个 resource owner。GitHub 当前还限制外部协作者用 fine-grained token 写入部分仓库，此时才考虑权限范围更大的 classic token。

2

保存并检查

检查过程不会创建测试评论。GitHub 没有无副作用的写权限探针，因此读取通过后仍需确认 Pull requests 显示为 Read and write。

本地保存 Token 只保存在当前 ego lite / Chromium profile 的扩展存储中，只发送给 api.github.com，不会进入 plan、评论或仓库。
