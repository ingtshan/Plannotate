PLANNOTATE · GITHUB ACCESS

连接 GitHub

推荐使用只覆盖需要评审仓库的 fine-grained personal access token。

尚未从 PR 获取目标仓库

1

创建正确权限的 token

在 GitHub 创建（已预填权限）
  1. Resource owner选择目标仓库的所有者
  2. Repository access选择 Only select repositories，并加入要评审的仓库
  3. Repository permissions按下表核对；不需要任何 Account 或 Organization permission
ContentsRead-only读取已提交的 plan HTML、manifest 与 anchors
Pull requestsRead and write读取、创建和回复 review thread
MetadataRead-onlyGitHub 自动附加

状态变更说明：GitHub 可能拒绝 fine-grained PAT 调用 GraphQL 的解决/重新打开接口，即使 Pull requests 已是 Read and write。Plannotate 会把这两个操作交回当前 PR 的 GitHub 原生 review，不需要扩大 token 权限；若网页尚未登录，GitHub 会先要求登录。

组织仓库、外部协作者或多个 owner

组织可能要求管理员批准或 SSO 授权；pending token 只能读公共资源。一个 fine-grained token 只能绑定一个 resource owner。外部协作者还可能受 fine-grained token 限制。只有必须由 CLI 自动解决/重开 thread 时，才考虑权限范围更大的 classic token：公共仓库使用 public_repo，私有仓库使用 repo。

2

保存并检查

检查过程不会创建测试评论。读取通过后仍需确认 Pull requests 显示为 Read and write；fine-grained PAT 的解决/重开会安全地转到 GitHub 原生 review。

本地保存 Token 只保存在当前 ego lite / Chromium profile 的扩展存储中，只发送给 api.github.com，不会进入 plan、评论或仓库。
