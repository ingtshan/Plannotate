Dogfood plan · v0001

Plannotate 的第一次自我评审

我们不再另造一个评审后台：计划是 PR 中的不可变 HTML，意见是 GitHub 原生 review thread，扩展和 CLI 只是两个同等客户端。这份文档就是第一个真实样本。

Owner: maintainersStage: public v0.1Decision window: this PR

这次 dogfood 要证明什么

成功不是“页面能打开”，而是一条从仓库到人、再回到仓库的可审计闭环。

01

无服务

扩展直连 GitHub API，没有中转 token 或复制评论的服务器。

02

可追溯

每个评论都绑定 PR head、artifact SHA、版本与稳定锚点。

03

可迭代

处理意见后只追加 v0002，旧语境不被覆盖或伪装成新版。

端到端流程

1 · Package把自包含 HTML 编译成 manifest、不可变版本和 anchor sidecar。
→
2 · Review扩展按 head SHA 读取并校验两条 SHA-256 链，沙箱内渲染。
→
3 · IterateCLI 拉取 thread，回复、resolve，然后生成下一个版本。

信任边界

GitHub 负责身份与授权；扩展负责校验与编排；plan 始终被当作不可信内容。任何元数据不一致都应 fail closed。

本 PR 的验收方式

  • 安装 ZIP 解压后的扩展，保存仅限当前仓库的 fine-grained token。
  • 打开这个 PR，点击右下角 Review rendered plan，确认 v0001 可见。
  • 对本行做块级评论，再选中一小段文字发送选区评论。
  • 回复并 resolve 预置的 dogfood thread，刷新后确认 GitHub 与扩展状态一致。
